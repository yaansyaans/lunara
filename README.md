# Lunara

Generated by [ProxDocs](https://github.com/crllect/ProxDocs). Package versions verified 2026-08-04.

## Run it

```bash
bun install
bun run start
```

The server listens on port 8080, or the first free port above it if that one is taken. Set `PORT` to choose a starting point.

### Features

- **Browser controls, tabs, history, bookmarks** as before.
- **Settings pop-up** (dock, `Ctrl+,`, or `lunara://settings`) with six tabs:
  Appearance (69 themes with light and dark versions, custom themes, glass mode,
  background image upload or link, 120 Google Fonts, Lexend by default),
  Preferences (search engine, proxy games, transport, wisp server, your own
  OpenAI-compatible AI provider), Cloaking (40 tab-cloak presets, focus cloaking,
  about:blank/blob launch, panic key), Data (Lunara CloudSync, JSON export, clearing
  data, reset), Legal, and About.
- **Games** (`lunara://games`): every game from all four [gmshelf](https://github.com/gmshelf)
  repos (seraph, ckv, truffled, ugs), with a source dropdown, per-source counts and a total.
  Game files are relayed through `/gm/` so HTML is served as HTML and workers work.
- **Movies & TV** (`lunara://movies`): TMDB search, trending, seasons and episodes; plays
  through [VidFast](https://vidfast.vc) in an embedded player, with a fallback that opens the
  stream through the proxy. The TMDB token stays on the server (`TMDB_READ_TOKEN`).
- **Music** (`lunara://music`): SoundCloud search and streaming, ported from the working
  source in [x8rr/music](https://github.com/x8rr/music). The player lives in the shell, so it
  keeps playing across tabs.
- **AI** (`lunara://ai`): Groq's free models with per-person daily credits (see below).
- **Shop and coins**: 30 Lunara coins every 5-7 searches, spent on chat titles, chat text
  styles and AI credits. Balances are kept on the server.
- **Chat**: one global room; titles and text styles bought in the shop show next to names.
- **Cloud** (`lunara://cloud`): links to cloud-gaming services, used with your own accounts.

## Configuration

Put secrets in `.env` (loaded automatically, never served). See `.env.example`.

| Variable | Default | Meaning |
| --- | --- | --- |
| `GROQ_API_KEY` | (none) | Enables lunara://ai |
| `TMDB_READ_TOKEN` | (none) | TMDB v4 read token for lunara://movies (`TMDB_API_KEY` also works) |
| `AI_DAILY_CREDITS` | 40 | Free AI credits per person per day |
| `AI_DAILY_CREDITS_PER_IP` | 400 | Free AI credits per network per day |
| `TRUST_PROXY` | off | Set to `1` behind a reverse proxy so limits use `X-Forwarded-For` |
| `SOUNDCLOUD_CLIENT_ID` | scraped | Pin a SoundCloud client_id instead of scraping one |
| `LUNARA_DATA_DIR` | `./data` | Where accounts and wallets are stored (`lunara.json`) |

### AI fairness

The whole server shares one Groq key, whose free tier allows roughly 1,000 requests a day
and a few thousand tokens a minute per model. So:

- one request at a time per person, with a 3 second cooldown;
- 40 free credits a day per person; GPT-OSS 20B and ALLaM cost 1, Qwen 2, GPT-OSS 120B 3;
- 400 free credits a day per network, so making new devices does not make new allowances;
- a server-wide daily budget per model just under Groq's cap;
- credits bought in the shop are used after the free ones, and failed requests are refunded.

## Where things are

```
server.js             static files + the tunnel endpoint
server/               accounts, coins/shop, AI, games relay, music, image relay
public/js/pages/      scripts for lunara://games, play, music, ai, shop, chat
public/js/engine.js   the ONLY file that talks to the proxy engine
public/js/app.js      DOM wiring; rewrite this freely
public/js/url.js      address-bar input -> URL
```

`engine.js` implements a small interface (`init`, `createSession`, `setTransport`).
Feature modules use that interface. Changing transports also changes server mounts,
dependencies, service-worker files, and transport setup.

It also pings the service worker every 15 seconds. That is not optional. Browsers
terminate an idle service worker after about thirty seconds, and Scramjet keeps its
routing table in the worker's module scope, so a cold worker cannot route and the
first navigation after a quiet period lands on this server's 404 instead. Removing
the interval reintroduces that bug.

## Requirements

- **HTTPS in production.** Service workers do not run on plain HTTP
  (localhost is exempt).
- **Cross-origin isolation.** The server sets `Cross-Origin-Opener-Policy`
  and `Cross-Origin-Embedder-Policy`. The engine does not need these to
  run, but it re-sends them onto proxied responses, which is what lets a
  proxied site use `SharedArrayBuffer`. Drop them and any site that needs
  it breaks from inside its own code. Keep them.
- **WebSockets.** The Wisp tunnel is a long-lived WebSocket, so serverless
  hosts will not work. Use a VPS, Render, Fly, Railway, or similar.

### The service worker keepalive

`engine.ts` pings the service worker every 15 seconds. That is a
workaround for an upstream bug, not something Scramjet asks for: browsers
terminate idle service workers, Scramjet's worker loses the frame prefixes
it was routing, and every navigation after that lands on this server's 404
until you reload. Posting a message resets the idle timer.

Delete it once upstream fixes the revive handshake.
